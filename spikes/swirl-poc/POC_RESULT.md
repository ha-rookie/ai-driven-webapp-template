# Swirling Motion PoC 検証結果

## 結論

PoCは成功と判断する。

成功条件は「ソムリエとして正しいスワリングを科学的に採点できること」ではなく、スマートフォン内蔵センサーだけで、スワリングを模した円〜楕円運動を単純往復・静止・乱暴な円運動から一定の再現性をもって区別できることとした。

同一Android端末・同一被験者による実機検証では、以下を確認した。

- 通常の円〜楕円運動を `orbit` と判定できる
- 左右往復・前後往復を `linear` と判定できる
- 静止を `static` と判定できる
- 激しい円運動を `orbit` のまま `vigorous` と区別できる
- 時計回り／反時計回りの方向候補を分離できる
- 直線往復や静止では品質スコアを算出しない階層型判定が機能する

## PoC v0.2 の判定構造

### Stage 1: 動作分類

優先順位を持って分類する。

1. `movementRms < staticRms` → `static`
2. `axisRatio < linearAxisRatio` → `linear`
3. `axisRatio >= orbitAxisRatio` → `orbit`
4. それ以外 → `borderline`

現行のPoC暫定しきい値:

- `staticRms = 0.12`
- `linearAxisRatio = 0.25`
- `orbitAxisRatio = 0.40`

これらは今回の実測から置いたPoC用暫定値であり、科学的基準・端末横断基準ではない。

### Stage 2: スワリング品質評価

`gesture = orbit` の場合だけ品質スコアを算出する。

評価要素:

- 姿勢安定性
- 円〜楕円らしさ
- 周期性
- 滑らかさ
- 強度コントロール

直線往復が周期的・滑らかでも品質スコアを出さない。これによりPoC v0.1で発生した「往復運動でも総合点が高く見える」問題を解消した。

## 第1ラウンド代表値

| パターン | gesture | intensity | axisRatio | movementRMS | quality |
| --- | --- | --- | ---: | ---: | ---: |
| A 通常スワリング | orbit | controlled | 0.883 | 4.179 | 89 |
| B 左右往復 | linear | controlled | 0.105 | 5.477 | N/A |
| C 前後往復 | linear | controlled | 0.131 | 4.099 | N/A |
| D 激しい円 | orbit | vigorous | 0.468 | 22.923 | 60 |
| E 静止 | static | static | 0.578 | 0.028 | N/A |

Eではセンサーノイズにより `axisRatio` や `rotationCoherence` が見かけ上高くなることがある。そのため、静止判定を最優先する階層構造が重要。

## 激しい円運動の特徴

PoC v0.1/v0.2を通して、激しい円運動は `orbit` が必ず低くなるわけではない。

通常スワリングとの差分として有効だったもの:

- `movementRms` の大幅増加
- `normalizedJerk` の増加
- 滑らかさの低下
- 強度コントロールの低下

したがって「円運動か」と「強すぎるか」は別軸で扱う。

## 回転方向

同じ右手で方向を明示して検証した結果:

- 時計回り → `rotationSign = negative`
- 反時計回り → `rotationSign = positive`

激しい円運動でも符号対応は維持された。

PoC v0.2では `axisRatio` と `rotationCoherence` を満たす場合のみ方向候補を表示する。

現行暫定値:

- `directionAxisRatio = 0.30`
- `directionCoherence = 0.55`

端末座標系・画面向き・OS差を未検証のため、時計回り／反時計回りの符号対応は一般化しない。

## 周期・テンポ

PoC v0.1のゼロクロス方式は、1周中の局所変動を周期として拾うケースがあり不安定だった。

PoC v0.2では自己相関ベースに変更した。

ただし、静止や直線往復でも周期値は数学的に算出できるため、UIでは `static` / `linear` 時に周期・テンポ・回転方向関連を `N/A` とする。JSONにはデバッグ目的で生の診断値を残す。

## 安全・表現上の制約

- スマホをしっかり持ち、周囲に人や物がないことを確認する
- 速さ・強さが高いほど高得点にはしない
- ワインの香り・味・品質をスマホが測定しているように表現しない
- 研究上の観測値を「理想の回転数」「正しい角度」と断定しない
- 回転方向に優劣を付けない

## 未検証

- 複数被験者
- 複数Android端末
- iPhone / Safari
- 画面向き変更時の座標系
- センサー取得レートが異なる端末
- 長時間利用
- 実際のワイングラスを持つ動作との一致度
- 公開用ゲームスコアの妥当性
