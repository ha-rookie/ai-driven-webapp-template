# くるくるソムリエ（仮） Product Brief

## 1. コンセプト

スマートフォンをワイングラスのように円〜楕円状に動かすと、端末内蔵センサーが動作を計測し、スワリングらしさ・滑らかさ・強度などをゲーム的に評価して、前向きなソムリエ風コメントで励ましてくれるWebアプリ。

**計測部分は本気、コメント部分はふざける。**

ワインそのものを分析するアプリではなく、あくまで「スワリングという所作」を楽しむアプリとする。

## 2. ユーザー価値

- 飲み会・ワイン会でその場が少し盛り上がる
- スワリングという身体動作をスマホだけでゲーム化できる
- 上手い／下手の断罪ではなく、どんな動きでもポジティブに返す
- センサーを使った“実際に動かす遊び”なので、単なる診断・占い系より体験性がある

## 3. 想定利用シーン

- ワインを飲んでいる場で「ちょっとやってみて」とスマホを渡す
- ワイン初心者がスワリングの動きをゲーム感覚で試す
- 飲み会のアイスブレイク
- 友人同士でタイプやコメントを見せ合う

## 4. MVPスコープ

### 必須

1. START
2. センサー利用許可
3. 基準姿勢キャリブレーション
4. 3秒カウントダウン
5. 5秒計測
6. 動作分類
7. スワリング候補のみ品質評価
8. スタイル名
9. ポジティブコメント
10. 再挑戦

### 判定

Stage 1:

- static
- linear
- borderline
- orbit

Stage 2 (`orbit` のみ):

- 姿勢安定性
- 円〜楕円らしさ
- 周期性
- 滑らかさ
- 強度コントロール

補助情報:

- controlled / vigorous
- 時計回り候補 / 反時計回り候補

### MVPでは不要

- ログイン
- DB
- ランキング
- ワインラベル認識
- 銘柄推薦
- AIソムリエ会話
- テイスティング記録
- SNSアカウント連携
- 実ワインの品質評価

## 5. 結果画面の方向性

技術スコアをそのまま突きつけるのではなく、まずタイプを返す。

例:

### エレガント型

円運動・滑らかさ・強度が安定。

コメント例:

> グラスの中に小さな舞踏会が開かれています。

### 情熱型

円運動は成立しているが強度が高い。

コメント例:

> ワインより先に情熱が回っています。

### クラシック型

姿勢安定性が高く、動きが比較的小さい。

### アヴァンギャルド型

境界的・個性的な軌道。

### 瞑想型

ほぼ静止。

コメント例:

> 静寂のスワリング。ワインと対話するタイプですね。

### 直線運動

失敗扱いにはしない。

コメント例:

> 今日はワインより振り子と気が合うようです。

※コメントは公開前にトーンレビューする。ユーザーを馬鹿にする表現にはしない。

## 6. 採点設計原則

- 分類と品質評価を分離する
- `orbit` ではない動作に品質総合点を出さない
- 速いほど高評価にしない
- 強すぎる動作は control を下げる
- 時計回り／反時計回りで得点差を付けない
- 「科学的に正しいスワリング点」とは表現しない
- 得点はゲーム用のプロダクト設計値として扱う

## 7. 技術構成（MVP案）

- Static HTML / CSS / JavaScript
- DeviceMotionEvent
- DeviceOrientationEvent
- Cloudflare Pages
- Backendなし
- 解析は端末内
- 個人情報・センサー時系列データをサーバー保存しない
- PWAはMVP後半または公開前に追加

## 8. UX上の安全対策

計測前に明示:

> スマホをしっかり持ち、周囲に人や物がないことを確認してください。

追加検討:

- 大振りを促さない説明
- 速度競争UIを作らない
- vigorous判定時も「もっと速く」等の誘導をしない
- 飲酒状態での利用を前提に、操作を最小化する

## 9. デザイン方向性

ワインレッド〜黒を基調にした大人向けだが、堅いソムリエ試験アプリにはしない。

候補:

- グラスを模した中心ビジュアル
- スマホの動きに合わせたワイン液面風アニメーション
- 結果時にタイプごとの短い演出
- 文字は視認性優先

流体表現はPoCのコアではないため、判定ロジック確定後に追加する。

## 10. 名前

会話上の仮称: **くるくるソムリエ**

正式名称決定前に以下を確認する。

- GitHub repository名
- Web検索
- App Store / Google Play
- 商標
- ドメイン
- SNSアカウント名

## 11. 成功指標（MVP）

技術:

- A/B/C/D/E相当の基本動作を実機で安定分類できる
- センサー非対応端末で適切にエラー表示できる
- iOS/Androidの主要ブラウザで利用可否が確認できる

体験:

- 説明なしでもSTARTから結果まで進める
- 結果を見て「もう一回やりたい」と思える
- 直線・静止でも不快な失敗体験にならない

## 12. PoCから引き継ぐ重要事項

詳細は `POC_RESULT.md` を参照。

特に以下を崩さない。

- static判定を最優先
- axisRatioを直線／2D軌道判定の主要特徴量として使う
- movementRMSを強度軸として独立させる
- normalizedJerkを滑らかさ評価に使う
- rotationSignは方向判定条件を満たす場合だけ意味を持たせる
- テンポ値はスワリング候補以外ではユーザー向けに表示しない
