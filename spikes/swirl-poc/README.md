# Swirling Motion PoC

Issue: #15 `spike: スワリング採点アプリのPoC成立性を検証する`

## 位置づけ

このディレクトリは新規アプリ候補の technical spike 用であり、テンプレートの標準機能ではない。

- Branch: `spike/issue-15-swirling-poc`
- mainへは原則マージしない

- PoC失敗時は結果と原因だけIssueへ記録して終了する

## 検証仮説

スマートフォンの `DeviceMotionEvent` と `DeviceOrientationEvent` を組み合わせることで、スワリングを模した小さな円〜楕円運動を、単純な左右／前後往復・静止・乱暴な動作から一定の再現性をもって区別できる。

## 評価対象

PoCではワインの香り、味、品質を評価しない。評価するのはスマートフォンの身体動作だけ。

### 1. 姿勢安定性

START時点の `beta` / `gamma` を基準姿勢とし、計測中の変動量・最大変位を使う。

### 2. 円・楕円らしさ

XY平面の加速度を平均中心化し、2次元共分散行列の固有値を求める。

- 円・楕円運動: 2方向に分散が存在する
- 単純往復: 一方向の分散が支配的になる

`minor / major` の固有値比を円・楕円らしさの主要指標とする。

### 3. リズム

主成分方向へ加速度を射影し、正方向ゼロクロス間隔から周期を推定する。周期の変動係数が小さいほど一定リズムとみなす。

### 4. 滑らかさ

連続サンプル間の加速度ベクトル変化を、運動全体のRMSで正規化して暫定評価する。急加速・急停止・振動が多いほど低評価とする。

## 静止判定

XY加速度RMSが小さすぎる場合は静止と判定し、円・楕円らしさ等が偶然高くならないよう総合点へゲートを掛ける。

閾値・重みはすべてPoC用の暫定値。実機データで調整する。

## 暫定総合スコア

- 姿勢安定性: 25%
- 円・楕円らしさ: 35%
- リズム: 20%
- 滑らかさ: 20%

ただし静止判定時は総合スコアを低く制限する。

## 実機テスト

各パターンを最低5回実施する。

| ID | 動作 | 期待 |
| --- | --- | --- |
| A | 小さな円〜楕円を一定リズムで回す | 最も高い |
| B | 左右だけ往復 | 軌道スコアが低い |
| C | 前後だけ往復 | 軌道スコアが低い |
| D | 激しく円運動 | 姿勢・滑らかさがAより低い |
| E | 静止 | 静止判定される |

## ブラウザ上の制約

- センサーAPIはHTTPS等の secure context が必要
- 一部ブラウザではユーザー操作を起点に明示的なセンサー権限要求が必要
- ブラウザ間でMotion座標系の扱いに差があるため、絶対値より相対・統計特徴を中心にPoCする
- `event.acceleration` が利用できない場合は `accelerationIncludingGravity` をフォールバックとして取得するが、精度差を診断表示する

## PoC画面

`index.html` は外部ライブラリ・外部通信なしの単一HTML。

- センサー対応状況表示
- センサー権限要求
- START → 5秒計測
- リアルタイム値表示
- 4軸スコア＋総合スコア
- 診断指標表示
- 測定結果JSONコピー

## 合格条件

Aが常に最高点になること自体を必須にしない。まず以下を満たすかを見る。

1. AとB/Cに軌道指標上の明確な差が出る
2. AとEを確実に区別できる
3. Dで姿勢または滑らかさの悪化を検出できる
4. 同一人物の類似動作で評価が極端にばらつかない
5. 実機ブラウザで5秒間のセンサー取得が安定する

これを満たした後、研究値やワイン専門知識を使って正式な採点モデルを設計する。
